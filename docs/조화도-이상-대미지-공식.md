## 1. 조화도 파괴 (Tune Break)

```
조화도 파괴 데미지 =
  기초값 10000
  × 조화도 파괴 배율
  × 조화도 파괴 부스트
  × 조화 치명
  × 속성저항
  × 방어저항
  × 조화도 피해 증가
  × 반복 횟수
```

| 항 | 내용 |
|---|---|
| 기초값 | **10000 고정.** 공명자의 공격력 등 개인 스탯과 무관하다 |
| 조화도 파괴 배율 | 스킬마다 정해진 고유 배율. 기본 조화도 파괴 스킬은 **1600%**, 공명자마다 다르다 |
| 부스트 | `(100 + 추가 조화도 파괴 부스트 수치) / 100`. 기본 100에서 시작하고 정수로 합산한 뒤 100으로 나눈다 |
| 조화 치명 | `1 + 조화 치명 확률 × (조화 치명 피해 − 1)`. 별도 치명 수치가 없으면 1.0 |
| 속성저항 | 일반 피해와 같은 규칙. **일반 조화도 파괴는 물리 피해**, 「파동」 유형 스킬만 고유 속성을 가진다 |
| 방어저항 | `(800 + 8×내레벨) / (800 + 8×내레벨 + (792 + 8×적레벨) × (1−방어무시) × (1−방어감소))` |
| 조화도 피해 증가 | `1 + 조화도 피해 증가% 합계` |
| 반복 | 같은 조화도 파괴가 여러 번 터질 때의 횟수. 기본 1 |

### 계산 예시 (원문 그대로)

```
기초값 10000 × 배율 16.0(1600%)
× 부스트 1.4        (추가 40pt)
× 속성저항 0.8      (적 물리 저항 20%)
× 방어저항 0.5013   (공명자 90 vs 적 90)
× 조화도 피해 증가 1
× 조화 치명 1.0
× 반복 1회
→ 최종 데미지 ≈ 89832
```

### 옮길 때 걸리는 것

- **기초값이 공격력이 아니다.** 지금 `Attack.scalingStat`은 ATK/HP/DEF뿐이라
  「고정 10000」을 담을 자리가 없다.
- **물리 저항이 필요하다.** `Enemy`에는 속성 저항이 `baseRes`/`sameElementRes` 두 칸뿐이고
  물리 저항은 따로 없다. 「파동」 유형만 속성 저항을 쓰므로 둘을 갈라야 한다.
- **조화도 전용 스탯 칸이 없다.** 조화도 파괴 부스트 · 조화도 피해 증가 · 조화 치명 확률/피해는
  `Stats`에 자리가 없다(`syncAmplify` 하나가 표시 전용으로 있을 뿐이다).

## 2. 이상 효과 (Anomaly)

```
이상 데미지 =
  이상 기초값
  × 발생 횟수
  × 부스트
  × 이상 치명
  × 방어저항
  × 속성저항
  × 최종피해
```

### 이상 기초값

```
이상 기초값 = B(L) × 원소 계수 × 스택 함수
```

- `B(L)`: 공명자 레벨별 기준값. **90레벨 = 3674**
- 원소 계수: 서리 효과 **203.77%** [10스택] / 불꽃 효과 **698.63%** [10스택] / 전자 효과 **415.85%** [10스택]

### 유형별

| 유형 | 효과 | 식 (90레벨 기준) |
|---|---|---|
| 틱데미지형 | 풍식 (Aero Erosion) | 1스택 `1654` / n스택 `4134 × (n−1)` |
| 틱데미지형 | 광학 (Spectro Frazzle) | 1스택 `898 × 1.235` / n스택 `898 × (n−1)` |
| 틱데미지형 | 전자 (Electro Flare) | `3674 × 0.41585 × n`, **매 틱 스택이 절반(내림)으로 줄며 감쇠 시리즈로 합산** |
| 스택폭발형 | 서리 (Frost Chafe) | `3674 × 2.0377 × (1 + α + 0.33 × over)` |
| 스택폭발형 | 불꽃 (Fusion Burst) | `3674 × 6.9863 × (1 + α + 0.33 × over)` |
| 디버프형 | 암흑 (Havoc Bane) | 피해 없음. `방어력 감소율 = 스택 × 2%` (최대 6%) |

- 틱데미지형: 스택이 유지되는 동안 일정 간격으로 발동하고, 발동마다 스택을 1 소모한다.
  피해는 현재 스택 수에 비례한다.
- 스택폭발형: 스택이 최대치에 닿으면 단발 대형 피해로 터진다.
  **발생 횟수 = 부착 수 ÷ 최대 스택.**
- `α`: 피해 배율 상승 효과(해당 효과를 가진 경우에만, 기본 0)
- `over = max(0, n − 10)`: 팀 버프로 최대 스택을 넘겼을 때 스택당 +33%.
  **`α`와 같은 항에 더해진다 — 따로 곱하지 않는다.**
- 암흑의 방어력 감소는 이상 피해에는 그대로 적용되고,
  일반 피해에서는 방어무시 효과와 **곱연산**된다.

### 공통 배율

```
× 발생횟수 × 부스트(1 + 부스트 수치) × 이상 치명 × 방어저항 × 속성저항 × 최종피해(1 + 총 피해)
```

**방어저항은 일반 피해와 다르다:**

```
방어저항 = (800 + 8×공명자레벨) / (800 + 8×공명자레벨 + (792 + 8×적레벨) × (1 − 방어감소))
```

> 이상 피해의 방어저항은 **방어무시(Ignore DEF)를 반영하지 않고 방어감소(Reduce DEF)만** 적용한다.
> 일반 피해는 둘 다 반영한다 — 이 차이가 핵심이다.

속성저항은 일반 피해와 같은 규칙이며, 원문은 `max(0, 0.8 + 저항무시)`로 적어 두었다
(적 저항 20% 기준값을 그대로 박아 쓴 형태다).

### 옮길 때 걸리는 것

- **기초값이 스탯이 아니라 레벨 표에서 나온다.** `B(L)`의 90레벨 값(3674)만 알려져 있고
  나머지 레벨 값은 원문에 없다.
- **스택·틱이 시간축 개념이다.** 지금 엔진은 「공격 한 번」 단위라 스택 감쇠 시리즈를 담을 자리가 없다.
- **방어저항 식이 일반 피해와 다르다.** `defMultiplier`를 그대로 쓰면 방어무시가 잘못 반영된다.
- **이상 치명 · 이상 부스트 칸이 `Stats`에 없다.**

## 3. 일반 피해 공식 — 우리 엔진과 대조한 결과

같은 사이트의 `wuthering_waves_damage_formula`도 함께 받아 두었다
(`api/phro/wuthering_waves_damage_formula.ko.json`). **지금 `src/calculator/damage.ts`와 일치한다.**

```
최종 데미지 = 스킬 계수 × 기초 공격력
  × 공격력 × 피해증가 × 크리티컬 × 부스트 × 속성저항 × 방어저항 × 받는피해 × 최종피해
```

| 항목 | Phro.Love | 우리 엔진 |
|---|---|---|
| 속성저항 | `1 − R` (0 ≤ R ≤ 0.8) / `1 − R/2` (R < 0) / `1 / (1 + 5R)` (R > 0.8) | `resMultiplier()` 동일 |
| 방어저항 | `(800+8×내레벨) / (800+8×내레벨 + (792+8×적레벨)×(1−방무)×(1−방감))` | `defMultiplier()` 동일 |
| 크리티컬 | `1 + 치명확률 × (치명피해 − 1)`, 기본 치명피해 150% | 동일 (`critDamage`는 100%를 뺀 보너스분) |
| 기본 저항 | 필드 몬스터 10% · 역경의 탑 20% | `ENEMY_RES_PRESETS`와 같음 |
| 부스트 · 받는피해 · 최종피해 | 각각 독립 곱연산 | 동일 |

차이가 하나 있다 — Phro.Love는 「스킬 계수 = 스킬 배율 × 피해 배율 × 피해 배율2」로 두고
배율 상승을 곱연산 자리(피해 배율2)에 담는데, 우리는 같은 것을
`motionValueAmplify`(곱연산) · `motionValueIncrease`(합연산) 두 칸으로 나눠 담는다.
결과는 같고 담는 모양만 다르다.
