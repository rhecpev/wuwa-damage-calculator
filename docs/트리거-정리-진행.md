# 공격 트리거 정리 — 진행표

공격이 **피해 말고 따로 일으키는 일**(이상 효과 추가·소모, 조화 밀집·파동 부여, 방어력 감소,
자원 수급 …)을 `src/data/attackTriggers.ts`에 모으고, 불러올 때 공격의 `trigger` 필드로 붙인다
(`sampleData.ts`의 `withTriggers`). 피해 계산은 이 값을 보지 않는다 — 루틴 카드와 화면이 읽는다.

## 담는 규칙

- **그 공격을 쓸 때** 일어나는 것만 담는다. 「파티 내 캐릭터가 …할 시」는 남의 공격이라 버프 쪽 일이다.
- 근거는 원문(`src/data/characterTexts.json`)에서 그대로 옮겨 `source`에 남긴다.
- 넷 중 하나만 채운다 — `anomaly`(6종 이상 효과) · `status`(조화 밀집·파동 「이탈」·「간섭」, 고유 상태)
  · `debuff`(방어력 감소 · 속성 저항 감소 · 받는 피해 증가) · `resource`(캐릭터 고유 자원).
- 수치를 모르면 `amount`를 비우고 `condition`에 「원문에 pt가 없다」처럼 적는다.
- 담지 않기로 한 것은 `attackTriggers.ts` 맨 위 TODO에 이유를 남긴다.

## 도구

```
npm run check:triggers                      # 적어 둔 것이 맞는가(근거 · 수치 · 중복 · 선언 누락)
node scripts/report-attack-triggers.mjs      # 캐릭터별 남은 문장 수
node scripts/report-attack-triggers.mjs 모니에  # 그 캐릭터의 아직 안 옮긴 문장
```

`check:triggers`는 오래 **CRLF 때문에 트리거를 0개로 읽어** 검사가 통째로 헛돌고 있었다(2026-09-16 고침).
숫자가 0개로 나오면 그때처럼 눈이 먼 것이니 먼저 의심한다.

## 회차

한 번에 끝내지 않고 **세 바퀴**를 돌았다(2026-09-16). 회차마다 보는 눈이 다르다.

1. **1회차 — 원문에서 뽑아 채우기.** `scripts/propose-attack-triggers.mjs`가 전 캐릭터의 원문에서
   「무엇을 얻고 · 태우고 · 붙인다」는 문장을 뽑아 공격 이름과 맞춰 초안을 내놓고, 그중 맞는 것만 담았다.
2. **2회차 — 갈래를 바꿔 다시.** 1회차가 안 보던 **디버프**(방어력 감소 · 속성 저항 감소 · 받는 피해 증가)와
   **이상 효과** 부여·소모 문장을 전 캐릭터에서 따로 훑었다.
3. **3회차 — 짝 맞춰 보기.** `node scripts/report-attack-triggers.mjs --pairs` — 자원마다 채우는 자리와
   태우는 자리가 짝을 이루는지 본다. 한쪽만 있으면 대개 빠뜨린 것이다(시간·파티 조건으로 도는 자원은
   한쪽만 있는 것이 맞고, 그 이유는 attackTriggers.ts 맨 위 TODO에 적혀 있다).

세 바퀴를 돌고 난 자리: 공격 1165개 중 **674개**에 트리거 **927줄**. 검사는 `npm run check:triggers`가
여섯 가지(없는 공격 id · 근거 없는 source · 어긋난 수치 · 선언 안 된 이상 효과 · 중복 · 조건 없는 모순)를 본다.
